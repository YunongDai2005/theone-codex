# TheOne Codex 移植验收清单

本清单是完整移植的验收目标，不能把所有条目视为已通过。首批 alpha 的实际覆盖、运行结果和缺口见 [实现记录](implementation-status.md)。协议导出和源码审阅不算功能验收。

## 核心闭环

| 场景 | 必须观察到的结果 | 证据 |
| --- | --- | --- |
| 两个独立主题交替说话 | A/B 分别有自己的上下文，回到 A 能继续原任务 | 脱敏输入、路由记录、thread/turn 对应关系 |
| 「继续」「按刚才的」 | 结合前台回复、待答项和暂离关系续接；后台通知不抢焦点 | 带展示顺序的完整事件记录 |
| A 运行时询问 B | B 的输入不混入 A；默认串行时明确排队 | 输入归属与两条会话的实际内容 |
| 明确更正「分错了」 | 旧运行停止或状态明确，重新归属一次，能查到纠错记录 | 两端 turn 终态及副作用记录 |
| 同一输入重复到达 | 不重复发起执行，不重复展示最终结果 | 持久化幂等键与宿主调用计数 |
| 主聊天转发工具结果 | 工具只执行一次；展示不产生第二次写入 | 测试文件内容或可计数模拟工具 |
| 模型路由异常 | 超时、无效 JSON、空结果有可解释退路，取消可生效 | 错误码、候选选择和回合状态 |

## 权限与执行

| 场景 | 通过条件 |
| --- | --- |
| 工作目录选择 | 只使用已允许项目；虚构/越界路径不被执行 |
| 同项目两条任务 | 按约定排队；验证排队取消和锁释放 |
| 多进程或重启 | 不能同时拥有同一话题的执行权；恢复不重复派单 |
| 审批允许/拒绝 | 回到原 thread/turn/request；拒绝不执行 |
| 过期或串线审批 | 明确无效，不能批准另一项待答请求 |
| 权限收紧或计划模式切换 | worker 使用有效权限，等待队列后再次核对 |
| hook 缺失、超时或未信任 | 不宣称已自动接管；普通聊天可理解地继续或提示需显式入口 |
| 历史中的指令文本 | 不覆盖当轮用户授权，不成为自动允许操作的理由 |
| 路由后的工具越界 | 仍由 Codex 的真实权限与沙箱处理，不能被插件绕过 |

## 状态与历史

1. 完成但未展示时重启：只补发已保存结果，工具不重做。
2. 执行中断时重启：说明实际进度与已发生副作用，接到继续请求后先核对现状。
3. 压缩后继续旧话题：重新补足失效简报；同样的资料在仍有效时不重复注入。
4. 未启用历史整理：不批量读旧聊天，也不为旧聊天发模型请求。
5. 排除某个项目或话题：检索、候选、简报、共享事实均不泄漏其内容。
6. 导入 DSH 副本：保留原始来源和映射，原库哈希不变；重复导入不重复创建。
7. 旧历史多页：遍历游标、处理空页和旧会话格式；实验搜索不可用时有退路。

## 原生桌面体验

在当前 Windows Codex 客户端上记录安装、启用、新聊天入口、话题目录、后台结果、追问、审批、取消、重启和卸载的真实行为。可选 MCP App 面板需要确认打开方式、状态同步与权限范围。

验收必须说明是否仍使用 Codex 原生主聊天、是否需要模型转述、后台工作是否显示在其他聊天、哪些工具卡片只能在话题会话中查看。自己的独立网页或 CLI 演示不等同于原生插件验收。

## 性能与准确性

同一组合法授权的输入，分别记录 DSH 固定基线与 Codex 候选的结果。统计跨话题误伤、话题碎片化、无必要澄清、错误工作目录、重复执行、端到端首字延迟、路由/worker/转述各自的用量。比较时保留模型、推理设置、网络条件与样本量。

先得到真实基线，再设可接受的量化门槛；不要沿用 README 的历史准确率或单价作为 Codex 承诺。确定性的权限、幂等、绑定和恢复场景应全部通过，任何串线审批或重复写入都需要修复后再验收。
