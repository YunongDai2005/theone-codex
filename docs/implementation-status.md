# 首批移植实现记录

日期：2026-11-09。插件版本：0.1.0-alpha.9；客户端适配：0.4.2。当前 UI 基线已改为远端 main `a943701` / DSH 0.4.6，细胞团代码原样复制，不再以旧版话题空间作为主入口。用户日常配置下的切换启动和体验确认仍与隔离副本检查分开记录。

## 历史整理并发与增量输出（alpha.9）

最多同时分类两段聊天，入库串行；后返回的新话题与刚新增的目录做语义核对，避免重复气泡，不仅凭标题合并。核对同样使用所选模型、思考强度与 Fast 档位，并计入每轮 64 次调用上限；余量不足时串行。已有话题只返回归属和变化字段，不重复生成标题、摘要和分组。达到扫描预算仍有可处理积压时，一秒后续跑；空闲、忙碌、失败和暂停不快速空转。

目录候选只解码最多 24 个描述，单话题用索引读取。消息清理按来源会话取引用和指纹，恢复中断后仅补缺失或过期投影，不再扫描全部正文或重写整段历史。

`history-pipeline-before.json` / `history-pipeline-after.json`：真实 Luna / medium / standard，同样 4 段合成聊天、16 轮，复用两个已有话题，39335 ms → 15149 ms（耗时减少约 61.5%）。4 次模型请求不变，并发峰值由 1 到 2；最终 JSON 大小 2060 → 606 字节（不是 token 或账单统计）。全部 32 条消息保留。

`history-pipeline-cold.json`：从空目录整理两段合成聊天，真实模型并发分类两次、核对一次，19735 ms，旅行延续复用同一话题，小说独立，共 2 个气泡和 6 条消息。此样本没有相同条件下的旧版首次整理耗时对照；不能把前面的 61.5% 用作首次全库整理的承诺。

`history-parallel-check.log`：132 项核心测试、类型检查和构建通过，覆盖并发上限、暂停、去重与独立事项、失效归属、删除防恢复、模型设置、额度、快速续跑、投影恢复和读取预算；`client-adapter-tests.log`：26 项客户端测试通过。实际用户的完整历史分类质量仍需使用验收。

本机 alpha.9 安装哈希与构建一致，43 个原生工具可发现，现有 Luna / medium / standard 设置和历史授权保持，见 `local-installation-ui.json`。`history-desktop-runtime.json` 于本次重跑通过：隔离原生客户端里入口、首次/手动整理、排除、模型/闪电选项、气泡生成和草稿保留均验证；历史及分类为受控样本，非用户全库。当前已打开的旧插件进程需要重启客户端加载新版本。

## 历史整理提速（alpha.8）

合批上限由 8 轮提高至 16 轮，同时用 9600 字符摘录预算约束批次；单轮超大摘录独立处理。校验器同步允许 16 个独立话题，仍强制每一轮完整且唯一归属。保持串行分类与入库，避免并发下目录过时、同一话题重复创建。没有降低中度思考，也没有自动开启快速。

`history-performance-before.json` / `history-performance-after.json`：同样 16 轮合成内容，2×8 轮总计 18078 ms，1×16 轮为 9368 ms，约减少 48% 耗时；启动和配置查询约 0.5 秒/批。该小样本不代表用户完整历史或长期服务延迟。最终回归见 `history-speed-check.log`（121 项核心测试、类型与构建）。

## 整理模型选择（alpha.7）

首次整理和后期手动整理提供实时模型目录、思考强度及 ⚡ 快速开关。默认优先 GPT-6 Luna、中度思考、标准速度；已有用户选择重启后继续沿用。没有已知经济模型时要求手动选择；失效模型或不支持的档位拒绝执行，不静默换模型。快速使用原生 serviceTier，关闭时显式指定 default，不继承 Codex 全局快速档位。运行中先暂停再改选；只处理后续增量，已完成历史不重做。

本次核心验证见 `history-model-check.log`（118 项、类型检查与构建），客户端单元验证见 `client-adapter-tests.log`（26 项）。`history-real-model.json` 记录 GPT-6 Luna / medium / standard 对两条合成输入的真实模型验证；历史界面验收仍使用合成历史和受控分类，详见 `history-desktop-runtime.json`。没有据此声称已验收用户完整历史分类质量或准确消耗。

## 原生历史整理（alpha.6）

首次点击 TheOne 询问是否整理旧聊天，支持跳过及后期从设置/管理话题手动启动。会话和文件夹筛选只读目录；用户同意后通过本机 App Server 读取完整或分页历史，使用现有 Codex 登录执行临时、结构化的模型分类。此阶段每批最多 8 轮（alpha.8 已改为按长度合批），每轮扫描最多 64 次模型调用；按稳定 turn ID 和内容指纹增量处理。

复用 DSH 的分类提示、完整轮次分配校验和原子话题入库。一个会话可拆分，多会话可归入同一话题，完成的批次自动进入原细胞组件；保留原会话引用和可检索摘录。支持暂停、失败重试、进程重启和多连接互斥；删除的话题不会被同一批历史重新生成。TheOne 自有话题会话更新独立于旧历史的许可。

原聊天不被改写。新增的原生历史许可与旧版 JSON 导入许可分开保存，升级不会因此自动启动全库模型整理。此版本不从原生历史接口提取不可用的压缩摘要，而是使用有长度上限的用户/助手摘录。后台工作依赖插件进程存活。

验证分别记录于 `history-implementation-check.log`（回归、类型、构建）、`history-real-model.json`（真实模型处理合成输入、真实原生历史读取结构）、`history-desktop-runtime.json`（隔离客户端、合成会话、真实 MCP 和原生编辑器）。这些证据不等于用户全部历史的分类质量验收。

## 原生界面入口

用户明确要求保留 Codex 原有聊天界面，并把 TheOne 按钮放在「新聊天 / 你的 dot」所在常驻操作区。插件的 `theone_open` 注册全局导航入口，单靠它不能满足指定位置；上面的客户端适配单独补足了该位置。插件界面通过官方 `ui/message` 的 `target: new, send: false` 请求打开预填启用内容的原生草稿。`theone_panel` 单独注册会话面板入口；选择或新建话题后将所选话题引用放入当前原生草稿，用户在原来的输入框继续。没有独立聊天输入框或回复区。

界面握手会检查宿主声明的 `openai/message` 能力；缺少能力时明确报不支持，不静默发送到别的会话。重复入口结果通知不会重复创建草稿。侧栏排序由宿主控制，协议没有按钮像素位置或「新聊天」相邻顺序字段。

- [原生界面桥接检查](../evidence/native-ui-validation.json)：真实 MCP 服务、Edge 与模拟原生宿主；8 项检查通过。包括草稿目标、重复通知、所选话题引用、新建话题、HTML 标题安全、无独立输入框及不支持宿主的处理。没有实际向用户聊天发送消息。
- [alpha.2 完整检查](../evidence/ui-implementation-check.log)：类型检查、90 项回归测试与构建通过。
- [alpha.2 隔离安装](../evidence/package-validation-ui.json)：33 个工具、技能及 UI 资源通过安装/协议验证。
- [当前本机安装](../evidence/local-installation-ui.json)：真实用户配置中的注册与资源读取检查；桌面视觉结果单独记录，不以协议检查代替。

早先制作过独立聊天页面测试原型；用户澄清后已从实现和发布包中移除，其图片与测试记录不作为当前交付证据。

桌面复查已排除「只需重启」作为完整解释。旧进程在 18:58:06 对 `theone_open` 深链接记录 `not-found`，随后桌面于 19:04:48 重启。重启后，当前聊天成功调用 alpha.2 的状态工具；无 thread 参数的全局 MCP 清单也发现了 33 个工具及 global/thread 元数据。更关键的是，运行桌面的 `mcp-global-entrypoints-v3` 持久化记录已包含 `gpt-theone@theone-local` / `theone_open` / alpha.2，确认真实桌面已登记全局入口。

用户随后确认在「探索 / 更多」中看到了 TheOne，并明确指出固定后所在的应用总导航不是所需位置。本机 26.1103.4239.0 客户端把 MCP 全局入口设为默认不显示；启用导航栏布局时，已固定的全局目的地由导航栏呈现，普通侧栏不再重复渲染这些目的地。公开扩展协议与本机入口 schema 均未提供向「新聊天 / 你的 dot」操作区插入第三方按钮的字段。这是插件扩展能力与目标位置之间的差距，不能用改工具名称、再固定或再重启解决。此诊断阶段没有修改客户端；随后获得用户明确授权，才实施上面的本机副本适配。历史见 [桌面诊断记录](../evidence/desktop-entrypoint-diagnosis.json) 与 [全局发现记录](../evidence/global-discovery-diagnosis.json)。

本轮按「先迁易做的功能」实施了通用核心、独立 Codex 工作会话和插件入口。不是只把 DSH API 改名，也没有宣称全部功能已等价迁移。原源码 50 个文件的哈希复查没有变化，见 [source-recheck.json](../evidence/source-recheck.json)。
